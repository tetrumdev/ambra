# pwnat investigation and validation — October 27, 2026

The optional pwnat path now completes authenticated Ambra pairing, exact WAV streaming, and reconnect through compatible **simulated** NATs on Kubuntu. Genuine public-Internet pwnat between the physical Mac and Kubuntu has **not been tested**, because the Mac requires the operator to run the dedicated ICMP launcher manually. No Mac password was requested, read, or used. There is no claim that arbitrary NATs work.

## Root causes

1. **Raw socket permissions were absent.** Kubuntu's Ambra executable had no `CAP_NET_RAW`. Its filesystem supported capabilities and was not mounted `nosuid`; its capability bounding set allowed `CAP_NET_RAW`. `/usr/bin/ping` had its own capability, which did not grant Ambra privileges. `net.ipv4.ping_group_range = 1 0` also denied unprivileged datagram ping sockets. UFW was inactive and host INPUT/FORWARD policy accepted traffic, apart from the existing Tailscale rules. No host firewall change was needed.
2. **The endpoint CLI silently lost its update.** The running-server CLI sent `publicEndpoint`, but `ConfigChange` expected `public_endpoint` and silently ignored the unknown field. Separately, no code published pwnat endpoint information through discovery. Previously paired clients therefore had no usable public hint.
3. **QUIC reconnect tried to bind a draining socket's fixed port.** The first real compatible-NAT run paired and streamed successfully, then reconnect failed with `Address already in use (os error 98)`. The connection manager now owns a reusable pwnat client endpoint. Session guards close old QUIC sessions explicitly.
4. **NAT assumptions were not satisfied by ordinary Linux client SNAT.** A fabricated Time Exceeded packet quotes a server flow unknown to the client's conntrack. Linux classifies it as INVALID and leaves its private source untranslated. A capability grant cannot repair this router behavior. The isolated test verifies that this case times out safely.
5. **Selection order and platform handling did not match an optional fallback.** pwnat preceded HyperDHT, and desktop Windows could attempt raw ICMP without a supported privilege path. Selection now prefers LAN, then HyperDHT, then optional pwnat. Windows, iOS, and Android skip pwnat explicitly.
6. **Capability and failure diagnostics were incomplete.** Capability detection registered a Tokio socket and therefore required a runtime. It now probes the OS socket without one. Echo/punch/setup errors, listener readiness, signed-publication failures, and authenticated public QUIC endpoints are reported separately.

## Changes

- Added a small C launcher that opens one IPv4 ICMP descriptor and drops privileges before executing the requested program. Linux clears process capabilities and sets `no_new_privs`. Ambra marks the inherited descriptor close-on-exec after adopting it. No sudoers changes, setuid executable, privileged Ambra process, or persistent privileged service is installed.
- Installed one root-owned helper on the disposable Kubuntu host at `/usr/local/libexec/ambra-icmp-launch`, mode `0750`, group `llewyn`, with `cap_net_raw=ep`. The server executable remains unprivileged and has no executable capabilities. The helper remains available for the prepared test; it is optional and removable.
- Added explicit `network pwnat on|off` server configuration, off by default. Listener lifecycle is separate from HyperDHT. Failed optional setup does not restart another transport.
- Added signed HyperDHT mutable endpoint records using the existing server key and public DHT. Only public IPv4 candidate and expiry information is published. Lifetime, schema, size, signature, address class, and port are validated. DHT-observed IP plus listener port is a conditional candidate, not a claim that the QUIC mapping was measured.
- Fixed the endpoint API field, kept the old snake_case alias, and added `network endpoint auto`. Invalid legacy saved hints are dropped without discarding server identity or paired devices.
- Added five-second pwnat setup bounds, bounded discovery, actionable privilege diagnostics, stricter ICMP quote checks, and explicit Windows/mobile exclusion. Existing bounded ICMP retries, rate limits, task limits, encryption, authorization, and mutation replay protection remain in place.
- Added portable regressions, native diagnostic probes, an isolated Linux NAT test, and a prepared macOS physical test. Client builds still contain no Ambra Server.

## Verified working

### Linux privilege boundary and ICMP

The helper ran a command with UID/EUID 1000, `CapEff: 0000000000000000`, and `NoNewPrivs: 1`. That command used its inherited ICMP socket successfully, but opening another raw socket failed with `Operation not permitted`.

An unprivileged helper-launched test sent an eight-byte Echo Request on loopback and received both ICMP types 8 and 0. A separate privileged observer captured Ambra's actual outgoing Echo on physical interface `wlo1`:

```text
192.168.86.220 > 192.0.2.1: ICMP echo request, id 8974, seq 42161, length 8
```

This proves host transmission, not Internet delivery or public NAT traversal.

### Compatible simulated NATs with actual Ambra processes

The final isolated test uses two NAT routers and a transit namespace on Kubuntu. It runs actual `ambra-server` and the shared native `pairing_probe`. The transit has no Internet route and no Tailscale interface. The client probe disables LAN/HyperDHT data attempts and asserts `ConnectedPwnat`. All test processes and namespaces are cleaned up.

The positive client NAT has an **explicit namespace-only stateless ICMP source rewrite**. This deliberately models a router that translates fabricated errors; ordinary Linux SNAT does not provide this behavior. Both NATs preserve the agreed UDP port. Unmapped inbound UDP is dropped instead of being accepted by the routers' own host stacks, avoiding competing confirmed tuples that can force port rewriting.

Verified behavior:

- Server receives and validates the actual Time Exceeded quotation.
- Server sends bounded punches from its QUIC listener.
- Transit capture contains both public simulation tuples `11.201.0.1:38149` and `11.202.0.1:38149`.
- QUIC and pinned Noise establish a direct stream.
- Real server approval, device-key binding, `/api/network/session`, enrollment replay rejection, and audio upload/ranges pass.
- The probe streams an eight-second, 44.1 kHz stereo WAV, **1,411,244 bytes**, with exact incremental byte comparison, then reconnects and verifies the same stream again.
- The final client remains `ConnectedPwnat`; no DHT application stream, LAN stream, VPN route, or relay carries these bytes.

Successful runs after the reconnect fix include 1,187/1,232 ms and 2,479/2,318 ms for the initial/reconnected WAV transfers. These are transfer timings, not a long-duration playback stability claim. The final test also checks an ICMP-blocking firewall counter, proving the blocking rule is exercised independently of the strict client-NAT failure.

### Physical Mac-to-Kubuntu discovery and preserved HyperDHT

The Mac used cellular hotspot address `172.20.10.12`, gateway `172.20.10.1`, interface `en0`. Kubuntu used `192.168.86.220`, gateway `192.168.86.1`, interface `wlo1`. Tailscale carried SSH management only.

An isolated unprivileged Kubuntu server, with the helper descriptor, automatically published signed candidate `74.104.161.161:38159`. The Mac's native `pwnat_probe lookup` fetched and verified it using only the server public key, without manually configuring an IP.

A separate native client then paired through the existing **HyperDHT** path. The client reported `ConnectedHyperDHT` and server endpoint `74.104.161.161:35369`; Kubuntu recorded the cellular peer at `174.224.164.234:64714`. The client uploaded/range-checked/streamed the exact WAV. It streamed again with pwnat disabled, then again after pwnat was enabled. All three transfers passed (12,485 ms, 12,387 ms, and 10,857 ms), and both session pings passed without changing transport.

These are real separate-network HyperDHT regression and signed-discovery results. They are **not pwnat NAT-traversal proof**. Hardware audio output was not exercised in this investigation.

## Verified failing

- Ordinary macOS raw socket creation: `Operation not permitted`.
- macOS unprivileged datagram Echo transmission works, but the necessary Time Exceeded transmission fails with `Invalid argument`.
- Ordinary Kubuntu raw socket creation without the helper/capability: `Operation not permitted`; datagram ICMP is denied by the configured ping group range.
- Ordinary Linux client conntrack SNAT in the isolated lab does not translate the fabricated error and cannot establish this pwnat connection.
- Blocking translated Time Exceeded traffic at the server NAT prevents setup; the actual rule counter increases and setup exits by its deadline. Server remains healthy.
- The pre-fix reconnect implementation bound the still-owned UDP port and failed. That failure is fixed and regression-tested.

## Not tested and remaining limits

- Genuine public-Internet pwnat between the physical Mac and Kubuntu: pending manual Mac helper execution.
- macOS privileged raw transmission/reception and the complete manual test script: prepared, not executed by the agent.
- Pwnat hardware playback, long-running endurance, and network-change recovery across physical routers: not tested.
- Windows native runtime and privilege broker: not implemented or tested; pwnat disabled. iOS/Android devices: not tested and pwnat disabled in normal sandboxes.
- NATs that randomize client UDP ports, rewrite the agreed ICMP identifier, reject related quotations, refuse client ICMP error translation, or filter the documentation destination can remain incompatible. No claim is made for arbitrary symmetric NAT, CGNAT, carrier firewalls, or all home routers.
- Simultaneous independent pwnat clients on one machine can compete for the protocol's agreed fixed UDP port. Per-manager reconnect now reuses its endpoint; the protocol is not extended to negotiate arbitrary client ports.
- DHT publication or lookup failure leaves no automatic hint unless the client has a valid cached/pairing endpoint. Records depend on sufficiently synchronized clocks. A disabled listener's old signed record can remain discoverable until its short expiry; the listener no longer accepts connections.
- No cryptographic audit, release packaging, production service change, commit, push, or PR was performed.
